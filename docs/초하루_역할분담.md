## 사람 1 — 저장 & 인증 (앱 기반)

**한 줄 목표**: 지금 가짜 데이터로 떠 있는 화면들을 진짜로 동작하게 만든다.

### 할 일

1. **일기 저장/조회 (AsyncStorage)**
   - 오늘 일기 쓰고 "저장" 누르면 실제로 기기에 저장되게
   - 날짜 키는 `YYYY-MM-DD` 문자열로 통일 (CLAUDE.md 코드 규칙)
   - 저장된 일기를 캘린더에서 다시 불러와서 보여주기
   - 오늘 이미 쓴 일기가 있으면 이어쓰기 (plan.md §7 [1])

2. **잠금 인증**
   - `expo-local-authentication`으로 기기에 이미 등록된 지문/Face ID 연동
   - 인증 실패·미지원 시 PIN 4자리로 대체
   - 백그라운드 30초 이상 → 재잠금 (plan.md §7 [0])
   - **로그인·회원가입 없음.** 계정 개념 자체를 만들지 않는다

3. **캘린더 완성**
   - 안 쓴 날 탭 → 그 날짜 일기 쓰기 화면으로 이동 (지금은 미구현)
   - "놓쳤다"가 아니라 "아직 안 썼다" — 실패 표시 절대 금지

4. **1일 자동 진입 로직**
   - 실제 오늘 날짜를 확인해서, 매달 1일 첫 실행이면 편지 화면으로 자동 진입
   - **데모 모드 토글 유지·보완** — 지금 잠금 화면 길게 누르면 켜지는 그 기능. 발표 당일(8/3) 실제로 1일이 아니므로 이게 없으면 편지를 못 띄운다

5. **편지함 화면 (plan.md P0 #9)**
   - 받은 편지 월별 리스트. 지금 6화면 스켈레톤엔 빠져 있던 화면
   - 12통이 모이면 "그 해의 책" 컨셉으로 확장 가능 (발표 자료용, 필수는 아님)

### 손댈 파일
- `App.tsx`, `src/screens/`, `src/theme.ts`, `src/ThemeContext.tsx` (기존 화면 스켈레톤)
- 새로 만들 파일: `src/storage.ts`(저장/조회 함수), `src/auth.ts`(인증 로직)

### 다른 사람에게 제일 먼저 공유해야 할 것
```ts
// src/storage.ts — 이 함수 시그니처를 제일 먼저 만들어서 공유
function getEntriesForMonth(yearMonth: string): DiaryEntry[]
```
사람 2가 "지난달 일기 가져오기"를 시작하려면 이 함수가 필요하다. (처음엔 mock 데이터를 그대로 반환하는 임시 버전이어도 됨 — 나중에 진짜 저장 로직으로 바꾸면 됨)

### 절대 하지 말 것
- 스트릭·달성률·연속 기록·배지 (게이미피케이션 전체 금지)
- 안 쓴 날에 X·빗금·회색 채움
- 서버로 일기 전송 — 기기 로컬이 원칙

## 사람 2 — AI 파이프라인 전반부 (신호 추출)

**한 줄 목표**: 한 달치 일기 뭉치에서 편지에 넣을 "재료"(특별한 문장들)를 찾아낸다.

### 파이프라인 구조 (plan.md §8)
```
지난달 일기
   ↓ ① 전처리 — 날짜 매핑 / 문장 분해   ← 코드
   ↓ ② 태깅 — 감정·주제 라벨링          ← LLM
   ↓ ③ 추출
      ├─ 반복된 감정   ← 코드 (빈도 집계)
      ├─ 사라진 걱정   ← 코드 (전반부 O, 후반부 X)
      └─ 말 안 한 노력 ← LLM (킬러 로직)
```
**여기까지가 사람 2 담당.** ④조립 ⑤검증은 사람 3.

### 할 일

1. **① 전처리 (코드)**
   - 일기 텍스트를 날짜별로 매핑
   - 문장 단위로 쪼개기 (편지 인용은 문장 단위여야 나중에 검증 가능)

2. **② 태깅 (LLM)**
   - 각 문장/일기에 감정·주제 라벨 붙이기
   - 프롬프트로 처리

3. **③ 추출 — 신호 3가지**
   - **반복된 감정**: 같은 걱정을 몇 번 썼는지 — 이건 코드로 빈도 집계 (LLM한테 세게 하지 말 것, 부정확함)
   - **사라진 걱정**: 전반부엔 계속 나오다 후반부에 사라진 주제 — 이것도 코드 로직 (전반/후반 절반 나눠서 등장 여부 비교)
   - **말 안 한 노력** (★ 킬러 로직, LLM): 아래 판별 기준으로 프롬프트 설계
     - 실제 행동·시도·지속을 서술하고
     - 서술이 짧고 담백하며 (자기 강조·감탄 없음)
     - 주변 문장에서 그 행동이 어렵다는 맥락이 확인됨
     - 예시: "동아리 면접 봤음. 손 떨렸는데 티는 안 났을 듯." — 대수롭지 않게 썼지만 사실 큰 도전이었던 문장

### 결과물 형태 (사람 3과 미리 합의할 타입)
```ts
interface ExtractedSignal {
  category: 'repeated' | 'faded' | 'unspoken_effort';
  quote: string;   // 원문 그대로, 한 글자도 수정 없음
  date: string;    // YYYY-MM-DD
}
```
이 배열을 만들어내는 게 최종 목표. 사람 3은 이 배열을 받아서 편지로 조립한다.

### 손댈 파일
- 새 폴더 `src/pipeline/` — `preprocess.ts`, `tagging.ts`, `extract.ts` 등으로 나눠서 작업 (기존 화면 파일은 거의 안 건드림)

### 주의할 점
- plan.md §10 안전 설계: 부정 감정 문장을 단독으로 나열하면 안 됨 — '지나갔음/버텼음' 맥락에서만 추출
- 좋았던 날·평범한 날도 신호로 같이 뽑아야 함 (조립 규칙 9번, 힘든 얘기만 모으면 실패)

## 사람 3 — AI 파이프라인 후반부 (조립·검증) + OCR

**한 줄 목표**: 사람 2가 찾은 재료로 진짜 편지를 완성하고, 사진 찍은 일기도 텍스트로 넣을 수 있게 한다.

### 할 일

1. **④ 조립 (LLM, plan.md §9가 사실상 이 작업의 전체 스펙)**
   - 사람 2가 만든 `ExtractedSignal[]`을 받아서 편지 한 통으로 이어붙이기
   - **화자는 AI가 아니라 "지난달의 나"** — 이게 이 앱의 핵심 가치
   - 형식: 인사 → 회상 → 다음 달의 나에게 한마디 → 서명("7월의 나로부터")
   - 인용은 4~6개, 그 사이 이어주는 문장은 AI가 작성
   - **금지 표현 목록 (프롬프트에 그대로 넣을 것, plan.md §9)**
     - 존댓말 전반
     - 평가·칭찬 어휘: 대단하다, 훌륭하다, 잘했다, 자랑스럽다
     - 조언·제안: ~해보자, ~하면 좋겠다, 다음 달엔
     - 집계 어투: N번 썼다, N일 중 N일, 빈도가 높다
     - 진단·분석 어투: ~로 보인다, ~한 경향이 있다, 패턴이 나타난다
     - 자기비판: 왜 이것밖에, 또, 여전히, 항상(부정 맥락)
   - **가장 흔한 실패는 요약 보고체** — 프롬프트에 규칙만 넣지 말고, `plan.md` §9의 "✅ 채택" 예시 편지 전문을 프롬프트에 그대로 넣어서 톤을 잡을 것 (plan.md §15 리스크 대응)

2. **⑤ 검증 (반드시 순수 코드, LLM 아님)**
   - 편지에 인용으로 표시된 문장이 원본 일기에 **정확히 존재하는지** 문자열 대조
   - 불일치하면 그 문장 제거하고 재조립
   - 각 인용에 원본 날짜를 붙여서 저장 → 편지 화면에서 탭하면 그 날짜 일기로 이동 (이미 화면 스켈레톤엔 이 탭 기능이 mock으로 구현돼 있음, 여기에 진짜 데이터 연결)
   - **이 단계를 LLM에게 맡기면 이 서비스의 근거가 사라진다** (CLAUDE.md 명시)

3. **OCR 연동 (Upstage Document Parse)**
   - 손글씨 다이어리 사진 → 텍스트 변환
   - 추출된 텍스트를 그대로 저장하지 말고, **수정 화면**을 거치게 할 것 (인식 오류 대비 안전장치, plan.md §7 [3])
   - 원본 이미지도 함께 저장 (일기 상세에서 다시 보여줘야 함)
   - **우선순위 가장 낮음** — plan.md §12 컷라인: 7/30 밤까지 편지가 안 나오면 OCR은 P1로 강등. 시간 부족하면 이 기능부터 포기해도 됨

### 손댈 파일
- 새 폴더 `src/pipeline/` — `assemble.ts`(조립), `verify.ts`(검증) — 사람 2와 폴더는 같이 쓰되 파일은 나눠서 충돌 방지
- 새 폴더 `src/ocr/`

### 먼저 할 수 있는 것
사람 2의 결과물을 기다릴 필요 없이, 가짜 `ExtractedSignal[]` 배열(직접 몇 개 만들어서)로 조립·검증 로직부터 먼저 짤 수 있음. 나중에 사람 2 결과물로 교체만 하면 됨.
